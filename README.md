A daily automated Telegram message with an original, LLM-generated motivational message for someone learning software engineering, powered by GitHub Actions and the Google Gemini API.

Every morning, a scheduled workflow runs a small Python script that asks an LLM to write a short, original motivational message and sends it straight to your Telegram chat — no server required.

## Features

- ⏰ Fully automated daily run via GitHub Actions (cron schedule + manual trigger)
- 🤖 A new, original motivational message every day, generated by the Google Gemini API
- 🎯 A system prompt tailored to someone learning software engineering (bugs, consistency, interviews, confidence, growth)
- 🔀 A randomly picked focus topic each day so consecutive messages don't feel the same
- 💬 Sends the message to Telegram through your own bot
- 🔐 No secrets in code — everything sensitive lives in GitHub Secrets
- 🧱 Small, typed, reusable functions with logging and clear error handling
- ✅ Pytest test suite covering the deterministic logic, run automatically on every push

## Tech Stack

- **Python 3.12**
- **[requests](https://pypi.org/project/requests/)** for HTTP calls
- **[Google Gemini API](https://ai.google.dev/api/generate-content)** for generating the motivational message
- **[Telegram Bot API](https://core.telegram.org/bots/api)** for message delivery
- **GitHub Actions** for scheduling, manual triggers, and running tests
- **GitHub Secrets** for credential storage
- **pytest** for automated tests

## How It Works

1. GitHub Actions triggers `main.py` on a schedule (or manually).
2. The script sends a request to the Google Gemini API (the `gemini-2.0-flash` model). The system prompt tells the model to write one short, original, encouraging message for someone learning software engineering, in natural English, around 80–150 words, never toxic, repetitive, or cheesy.
3. A random topic (e.g. "overcoming a difficult bug", "technical interviews", "staying consistent") is added to the request each time, so the daily messages don't all sound alike.
4. The generated text is wrapped in a simple template:

   ```
   🚀 Good morning!

   <generated message>

   Have an amazing day! ❤️
   ```
5. The final message is sent to your Telegram chat via the Telegram Bot API.

## Setup

### 1. Get Your Telegram Bot Token and Chat ID

If you already have a bot (like this project's own "Motivation Bot"), you can skip straight to grabbing its token and chat ID. Otherwise:

1. Open Telegram and start a chat with [@BotFather](https://t.me/BotFather).
2. Send `/newbot` and follow the prompts (choose a name and a username ending in `bot`). BotFather replies with a token that looks like `123456789:ABCdefGhIJKlmNoPQRstuVwxYZ` — this is your `TELEGRAM_TOKEN`.
3. Send any message to your bot so it has something to read.
4. In a browser, visit `https://api.telegram.org/bot<YOUR_TOKEN>/getUpdates` and look for `"chat":{"id": ...}` in the response — that number is your `TELEGRAM_CHAT_ID`.
   - If the response is empty, make sure you've messaged the bot first, then refresh.

### 2. Get a Gemini API Key

1. Go to [Google AI Studio](https://aistudio.google.com/apikey) and sign in with a Google account.
2. Click **Create API key**. This is your `GEMINI_API_KEY`.
3. Gemini has a free tier that's generous enough for one short message a day — no billing setup is required to get started.

### 3. Configure GitHub Secrets

In your GitHub repository, go to **Settings → Secrets and variables → Actions → New repository secret** and add:

| Secret name | Example value | Description |
|---|---|---|
| `GEMINI_API_KEY` | `AIzaSy...` | Your Google Gemini API key |
| `TELEGRAM_TOKEN` | `123456789:ABCdef...` | Your bot's token from BotFather |
| `TELEGRAM_CHAT_ID` | `987654321` | The chat that should receive the message |

### 4. How GitHub Actions Runs the Bot

The workflow at [.github/workflows/motivation.yml](.github/workflows/motivation.yml) does two things:

- **Scheduled run:** the `cron: "0 6 * * *"` entry runs the script every day at 06:00 UTC. GitHub Actions cron always runs in UTC and has no daylight-saving awareness, so the same entry maps to two different local times across the year. For example, in Israel (Asia/Jerusalem):
  - **Israel Daylight Time** (late March–late October, UTC+3): 06:00 UTC → **09:00 local**
  - **Israel Standard Time** (rest of the year, UTC+2): 06:00 UTC → **08:00 local**

  Adjust the cron hour to match when you want the message to land in your own timezone; expect a ~1 hour seasonal drift unless your zone doesn't observe DST.
- **Manual run:** thanks to `workflow_dispatch`, you can trigger the workflow on demand from the **Actions** tab, useful for testing your secrets and setup.

> **Note:** GitHub automatically disables scheduled workflows on a repository after 60 days with no commits. If the daily message suddenly stops, check the **Actions** tab and re-enable the workflow (or push a small commit to reset the clock).

### 5. Run Locally (Optional)

```bash
pip install -r requirements.txt

export GEMINI_API_KEY="your-gemini-key"
export TELEGRAM_TOKEN="your-telegram-token"
export TELEGRAM_CHAT_ID="your-chat-id"

python main.py
```

### 6. Running Tests

The project has a small pytest suite covering the deterministic logic in `main.py`: formatting the final Telegram message and reading configuration from environment variables. The generated motivational text itself is not deterministic, so it isn't tested — only that the surrounding code handles it correctly.

```bash
pip install -r requirements.txt
pytest -v
```

The workflow at [.github/workflows/tests.yml](.github/workflows/tests.yml) runs this same suite automatically on every push and pull request.

## Why I Built This

I built this project to practice working with real external services end to end, not just in an isolated exercise. Specifically, I wanted hands-on experience with:

- Writing clean, readable Python (functions, type hints, error handling, logging)
- Calling an LLM API and working with its response (the Google Gemini API)
- Writing a system prompt that reliably produces the tone and length I want
- Sending messages through the Telegram Bot API
- Automating a script to run on a schedule with GitHub Actions
- Keeping credentials out of the code using GitHub Secrets
- Writing automated tests with pytest
- Setting up a simple CI workflow that runs those tests automatically

## What I Learned

A few things I hadn't thought about before came up while building this:

- Prompting for "no clichés" doesn't fully guarantee it — I had to be specific in the system prompt about tone, length, and topics to get consistently useful output.
- Nudging the model with a different topic each run (bugs, interviews, consistency, and so on) is a simple way to get variety without any real complexity.
- Switching LLM providers partway through the project showed me that different providers structure their REST APIs quite differently (system prompts, message roles, and the shape of the response are all a bit different), even though the underlying idea — send a prompt, get generated text back — is the same.
- Since the LLM's output isn't deterministic, I could only unit test the code around it — the message template and the configuration loading — not the generated text itself.
- GitHub Actions cron schedules always run in UTC, so I had to work out how that maps to my own timezone, including the extra hour of drift from daylight saving time.
- For a project this size, a single script was enough — I didn't need extra folders, classes, or layers of abstraction on top of it.

## Future Improvements

- Keep a short history of recent messages and ask the model to avoid repeating themes
- Support sending to multiple chats at once
- Let the model pick the day's topic itself instead of a random list
- Add a retry with backoff if the Gemini or Telegram request fails
- Send a fallback message if the API call fails, so silence doesn't go unnoticed
